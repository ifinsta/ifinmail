{% trans 'Install' %}

{% trans 'On the server, as root or with sudo, run the installer. It installs Docker, fetches the platform, asks for your domain and administrator email, and starts every service.' %}

{{ install_command }}

{% trans 'To run it without questions, set the domain and email first:' %}

export DOMAIN=example.com ADMIN_EMAIL=admin@example.com
{{ install_command }} -s -- --non-interactive

{% trans 'Cloud providers that support cloud-init can use the cloud-init file in the repository instead.' %}

{% trans 'First setup' %}

{% trans 'Open the console at https://mail.your-domain/accounts/login/ and sign in with the administrator email and the password printed by the installer. You are asked to choose a new password, then taken through the setup wizard:' %}

  1. {% trans 'Domain: confirm the domain. Its DKIM key and the postmaster and abuse aliases are created.' %}
  2. {% trans 'DNS: connect a DNS provider to publish the records, or copy them to where the domain is hosted.' %}
  3. {% trans 'Account: create your own mailbox and administrator login.' %}

{% trans 'System health then shows what is left to do.' %}

{% trans 'DNS and delegation' %}

{% trans 'By default this server answers DNS for your domains. At your registrar, set the domain’s nameservers to ns1 and ns2 of the mail host and add them as glue records pointing at the server address. The console shows exactly what is missing and re-checks live. Once the zone is delegated, add the DS record it shows to switch DNSSEC on.' %}

{% trans 'If you keep DNS elsewhere, connect Cloudflare, Porkbun or DigitalOcean from the domain’s page, or mark it as external and add the listed records by hand.' %}

{% trans 'Ask your server provider to set the reverse DNS (PTR) of the address to the mail hostname. Many receivers check it.' %}

{% trans 'Daily operation' %}

{% trans 'Run these on the server from the install directory.' %}

sudo make version     # installed version and the latest release
sudo make update      # update to the latest release
sudo make rollback    # return to the version before the last update
sudo make health      # run the health checks
sudo make backup      # run a full backup now

{% trans 'An update snapshots the database first and rolls itself back if the new console is not healthy within five minutes. Mail, DNSSEC keys and certificates live in volumes that every version shares.' %}

{% trans 'Backups' %}

{% trans 'A daily encrypted backup is scheduled by the installer. By default it stays on the same disk, so do two more things:' %}

  • {% trans 'Set an off-site target (any machine you reach over SSH) and run the offsite check. Every backup is then copied and compared by hash.' %}
  • {% trans 'Export the backup key once, store it away from the server, and delete it from the server. System health confirms the key can open the newest backup.' %}

{% trans 'API' %}

{% trans 'Programs can manage mailboxes, aliases and domains over a versioned HTTP API. An administrator creates a key under Settings, then API keys: a key that is safe to log, and a secret that is shown once. Scopes can never exceed what the administrator holds.' %}

curl -u ifm_KEY:ifs_SECRET https://mail.your-domain/api/v1/mailboxes

curl -u ifm_KEY:ifs_SECRET -X POST https://mail.your-domain/api/v1/mailboxes \
  -H "Content-Type: application/json" \
  -d '{"address": "ana@example.com", "password": "a long passphrase"}'
  • {% trans 'The contract is at /api/v1/openapi.json, and /api/lists the versions this server speaks.' %}
  • {% trans 'Within version 1 only additions are made. A breaking change is a new version beside it.' %}
  • {% trans 'Lists are paged with limit and offset. Errors are JSON with a detail message. A key has a calls-per-minute limit and answers 429 with Retry-After when it is exceeded.' %}
  • {% trans 'Logins with console access cannot be changed through the API, and domains cannot be removed through it.' %}
  • {% trans 'To send mail, create a key with the mail.send scope and the addresses it may send as, then POST /api/v1/messages with from, to, subject and text or html. A 202 answer means the server accepted the message for delivery. Send an Idempotency-Key header so a retry never sends twice.' %}
  • {% trans 'GET /api/v1/health needs no key and is safe to poll from a monitor. The detailed health, DNS, deliverability and error-log reports need a key with the audit.view scope.' %}
  • {% trans 'The assistant knows the API and your keys: ask it how to connect a program, or whether your keys are set up safely.' %}
  • {% trans 'Rotate a key with an overlap so the integration can switch secrets without an outage. Every change is in the audit trail under the key’s name.' %}

{% trans 'Troubleshooting' %}

{% trans 'Port 25 is blocked' %}

{% trans 'Ask your server provider to unblock it. Without it the server cannot receive mail from other servers.' %}

{% trans 'The certificate was not issued' %}

{% trans 'The mail host and every domain’s client-configuration names must resolve to this server, and port 80 must be open. Use Issue now on the certificates page after DNS has propagated.' %}

{% trans 'Mail goes to spam' %}

{% trans 'Fix every failing check in System health, set the reverse DNS, and send small volumes at first: a new address has no reputation yet.' %}

{% trans 'A mail app cannot connect' %}

{% trans 'Use the full email address as the username, the mail hostname as the server, IMAP on port 993 with TLS, and SMTP on port 587 with STARTTLS or 465 with TLS.' %}
